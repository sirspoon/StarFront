# StarFront

A real-time squad tactics game (Close Combat style) in an original grimdark gothic sci-fi
setting, made with Godot 4 (4.3+, GL Compatibility renderer, GDScript). See `README.md` for the
layout and `docs/STYLE_GUIDE.md` for the setting.

## Workflow
- Commit and push straight to `main`. The owner pulls and runs it in the Godot editor on their PC.
- Every change to the game bumps the version by 0.01: `VERSION` in `scripts/game_data.gd` and
  `config/version` in `project.godot`. Add an entry at the top of `CHANGELOG.md` (version, date,
  what changed in plain words).
- The setting must stay original: no Warhammer 40,000 (Games Workshop) names, factions, symbols or
  designs. Keep the gothic grimdark feel, but with our own names and looks.

## Code
- Scenes are built in code from `scenes/main.tscn` -> `scripts/main.gd`, so there is little to edit in
  the editor. Classes use `class_name`. Map units: 1 cell = 16 px.
- The art is placeholder, drawn with `_draw()`. Real sprites are expected to replace `Soldier._draw`
  and the map drawing later (see the style guide).
- The map is painted by `MapPainter` into 20x20-cell tiles at 2x resolution (`MapView`), repainted when
  `BattleMap.cells_changed` fires. Painting must stay deterministic per cell (hash-seeded), so a
  repaint only changes what was destroyed. Damage repaints 5x5-cell patches laid over the tiles,
  shown straight from their viewports (no read-back). Nothing is painted in headless runs.

## Web version
- `.github/workflows/web.yml` exports the web build (`export_presets.cfg`, preset "Web", no threads,
  so it runs on GitHub Pages without special headers) and deploys it to Pages on every push to main.
- Touch controls switch on with a touch screen (or `--touch`); on phones the UI is laid out for a
  screen about 620 points tall. Emulated mouse events from touches are ignored in `main.gd`.
- To test the web build here: download `Godot_v4.3-stable_export_templates.tpz` (resume with
  `curl -C -` if the connection drops), put `templates/web_nothreads_release.zip` and `version.txt` in
  `~/.local/share/godot/export_templates/4.3.stable/`, export, serve `build/web`, and drive it with
  `tools/web_touch_test.js` (Playwright, emulated Pixel 7 sideways).

## Testing (in a cloud session)
- Get Godot: download `Godot_v4.3-stable_linux.x86_64.zip` from the godotengine/godot GitHub releases.
- Check scripts: `godot --headless --import`, then run the game headless.
- `GODOT=path/to/godot tools/autotest.sh [first_seed] [count]` plays computer-vs-computer battles
  (~10 s each) and prints the winner, shots, hits, dead and fled per side, and any script errors.
- Screenshots: `xvfb-run -a -s "-screen 0 1600x900x24" godot --rendering-driver opengl3 --fixed-fps 20 -- --autotest --seed=3 --shot=out.png --shot-time=40 --shot-zoom=2`
  (centres on the fighting at the given battle time). Add `--shot-vehicles` to centre on a vehicle,
  `--shot-tank` for a tank, `--shot-team=0|1` to pick a side, `--shot-at=x,y` for a map position,
  `--shot-wall` for the last wall to fall. `--demo-damage` shells the chapel's west wall at the start
  (to see every damage stage); `--log-walls` prints where walls fall. Rendering under xvfb is software,
  so a full battle there takes a minute or two.
- Performance: `--perf` prints the slowest frame every 40 frames (and how long each repair patch takes
  to paint); `--perf-blast` fires three tank shells into a wall once the map is drawn (`--perf-open`: open ground).
- Sounds are generated by `python3 tools/make_sounds.py` (needs numpy) into `sounds/`; `scripts/sfx.gd` plays
  them (one sound per weapon burst, the weapon -> sound table is `Sfx.WEAPON_SOUND`).
- Voice lines: `python3 tools/make_voices.py` (needs `pip install piper-tts` and the Piper voice
  en_GB-alan-medium, see the top of the script); `Sfx.voice()` plays acknowledgements. `--side=sworn
  --test-voice` (with `--autotest`, under xvfb) checks a move and a target order each get a reply.
- `--shot-melee` waits (after `--shot-time`) for a close fight and centres the screenshot on it;
  `--debug-assault` prints where the assault squads are and what they're doing every 10 s. Test
  results also print close-combat blows, melee kills and each assault squad's kills.
- `--prone` puts the Legion in the Down stance (for screenshots and balance runs); `--shot-squad=N` centres a
  screenshot on the player's Nth squad.
- `--no-flank` / `--no-ai-flank` turn off flanking (and crossfire) / the computer's flanking moves, for
  balance comparisons. Balance needs ~48 battles per setting to see a real difference.
- `--test-follow` orders the player's squads to move every few seconds during a real battle and prints any
  soldier who didn't go, with his state.
- `--test-touch` gives orders the way a phone does (tap, double-tap, hold-drag, hold) with nobody fighting;
  `--no-enemy` with `--test-follow` does the same for direct orders; `--test-reach` counts unreachable
  destination spots. All print anyone who did not move.
- `--test-carrier` checks one tap on a carrier selects it and a double tap boards the selected infantry.
- `--test-orders` (with `--autotest`, headless is fine) runs a line order and a picked-soldier move and
  prints where the men ended up and whether the squad stayed in contact. `--shot-select` selects the
  player's squads for a screenshot (shows links and facing arrows).
- Lighting checks: `--test-light=x,y` adds a strong light at a map position; `--debug-normals` shows
  the normal maps instead of the map colours. Normal maps come from `HeightPainter` +
  `scripts/normal_from_height.gdshader` (Godot reads green as "facing up the screen", hence `flip_y`).
